# ADR-001: Bounded and reproducible MVP

**English** | [Español](../es/adr/001-mvp.md)

Status: initial implementation decision. Date: 2026-11-10.

## Scope

SME cases only, in USD, with complete annual periods and standalone financial statements. Supported inputs are text-based PDFs and UTF-8 CSV files. OCR, currency conversion, corporate cases, consolidation, and partial periods are out of scope. An unsupported case produces an explicit limitation and blocks the financial draft rather than inferring missing data.

## Decisions

1. Policy selection is deterministic by segment, currency, accounting basis, and cutoff date: `valid_from <= cutoff < valid_to`, with no upper bound when `valid_to` is null. Exactly one version must match; zero or multiple matches block evaluation. Published policies are immutable and cannot overlap within the same scope.
2. Retrieval uses only fragments from the selected version. The engine executes structured rules published with that version. A conflict between policy text and rules blocks publication. RAG provides citations; it does not choose thresholds.
3. Each evaluation pins document hashes, policy, rules, formulas, parser, model, prompts, and configuration. New documents or policies create a new evaluation without modifying previous results.
4. Financial amounts use Decimal, persist as NUMERIC, and travel as strings rather than floats. Ratios are compared before rounding and displayed to four decimal places with ROUND_HALF_UP. USD amounts display two decimal places. Currency conversion is excluded.
5. DSCR equals annual cash available for debt service divided by annual debt service. Zero debt service produces NOT_APPLICABLE; negative debt service produces INVALID_INPUT. Negative cash flow with positive debt service yields a valid negative ratio. EBITDA does not replace available cash flow. Missing inputs prevent calculation. The example threshold of 1.20 is synthetic.
6. An explicit Python state machine orchestrates PostgreSQL-backed jobs with leases, heartbeats, bounded retries, and idempotency keys. Temporal, Kafka, MCP, and Kubernetes require measurements that justify each dependency before adoption.
7. Only a human reviewer resolves a case and cannot review an evaluation they prepared. Every review requires a reason, including approval. Outcomes are simulations.
8. Audit events are append-only with restricted privileges and a per-case hash chain. This supports tamper detection under documented assumptions; an administrator with full control can alter the system. Absolute immutability is not guaranteed.

## Consequences

The narrower scope supports unambiguous comparisons of financial values and evidence. Basic durable persistence remains mandatory even though Temporal is optional. Scope extensions require new architecture decisions and corresponding tests.
