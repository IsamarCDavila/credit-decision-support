# ADR-001: MVP acotado y reproducible

Estado: decisión inicial para implementación, 2026-11-10.

## Alcance

Solo PyME, USD, periodos anuales completos y estados individuales. PDF con texto y CSV UTF-8; OCR, conversiones de moneda, corporativos, consolidación y periodos parciales quedan fuera. Ingresar un caso fuera de alcance produce una limitación explícita y bloquea el borrador financiero, sin inferir datos.

## Decisiones

1. La selección de política es determinista por segmento, moneda, base contable y fecha de corte: `valid_from <= cutoff < valid_to` (sin límite superior si es null). Exactamente una coincidencia; cero o varias bloquean la evaluación. Las políticas publicadas son inmutables y no pueden solaparse para el mismo ámbito.
2. El índice recupera únicamente fragmentos de la versión seleccionada. El motor ejecuta reglas estructuradas publicadas con esa misma versión. Un conflicto entre texto y reglas bloquea su publicación. RAG aporta citas; no decide umbrales.
3. Cada ejecución fija documentos por hash, política, reglas, fórmulas, parser, modelo, prompts y configuración. Nuevos documentos o política crean una nueva evaluación; no mutan una anterior.
4. Cantidades Decimal, guardadas como NUMERIC y transportadas como cadenas; no float. Ratios se comparan sin redondear y se presentan a cuatro decimales con ROUND_HALF_UP. USD se presenta a dos decimales. No hay conversión monetaria.
5. DSCR = flujo disponible anual / servicio de deuda anual. Servicio cero produce NOT_APPLICABLE, negativo INVALID_INPUT; flujo negativo y servicio positivo produce ratio negativo válido. No sustituir flujo disponible por EBITDA. Cualquier entrada faltante impide calcular. El umbral de ejemplo 1.20 es sintético.
6. Orquestación explícita en Python; jobs persistidos en PostgreSQL con lease, heartbeat, reintentos limitados y claves de idempotencia. Temporal, Kafka, MCP y Kubernetes se posponen hasta que una medición justifique cada dependencia.
7. Solo un reviewer humano resuelve el expediente; no puede revisar una evaluación que haya preparado él mismo. La revisión requiere motivo incluso al aprobar. La resolución es de simulación.
8. Auditoría append-only con privilegios restringidos y hash encadenado por expediente. Esto permite detectar alteraciones bajo supuestos documentados; un administrador con control total puede alterar el sistema. No se promete inmutabilidad absoluta.

## Consecuencias

El MVP admite menos formatos y casos, pero permite comparar cifras y evidencias de forma inequívoca. La infraestructura de persistencia durable básica es obligatoria aunque Temporal sea opcional. El alcance puede ampliarse mediante nuevos ADR tras cerrar las pruebas.
