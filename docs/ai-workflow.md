# Grounded AI workflow

**English** | [Español](es/ai-workflow.md)

Phase 4 adds an OpenAI adapter and a bounded orchestration workflow for synthetic credit-analysis drafts. It supports the existing structured CSV and text PDF formats. Narrative statements, OCR, autonomous planning, and production credit decisions are outside this milestone.

## Processing contract

1. An analyst uploads synthetic statements and completes `/v1/cases/{id}/extract`.
2. `POST /v1/cases/{id}/ai-evaluate` pins that extraction's current document set, policy content hash, formula, provider, model, workflow, and prompt version.
3. The extraction role proposes observations with source IDs and verbatim raw values. A deterministic validator requires every supported nonblank observation, including conflicting duplicates, and every missing key. Unknown sources, changed amounts, omissions, and unsupported fields fail validation.
4. Deterministic tools reconstruct source-backed facts, calculate DSCR, and evaluate the pinned policy. The model cannot change these tools or their results.
5. The drafting role selects and orders verified claim cards. The renderer supplies material English and Spanish wording and evidence, fact, calculation, and policy-fragment references. Unsupported IDs, duplicate findings, omitted required findings, or invalid sections fail validation.
6. A successful job produces an immutable `DRAFT_READY` evaluation with an `ai_draft`. It remains **SIMULATION**, **DRAFT_ONLY**, and subject to independent human review.

This is deliberately constrained model-assisted extraction and organization. The parser already recognizes supported field labels; the model does not add narrative understanding. Claim wording is generated by code, so grounded output is not evidence of a general-purpose model's free-text reliability.

## Workflows and API

```json
{
  "source_evaluation_id": "<successful-extraction-uuid>",
  "provider": "mock",
  "workflow": "multi_agent"
}
```

Use the existing bearer identity and `Idempotency-Key` header. Only an analyst assigned to the case can queue analysis. The source extraction must match the current document set. Equivalent inputs reuse the existing evaluation; a new idempotency key does not silently rerun a paid call.

| Workflow | Model stages | Tool access | Total output-token cap |
|---|---|---|---|
| `generalist` | One combined extraction and claim-ID selection | Deterministic tools run after proposal validation | 4,096 |
| `multi_agent` | Extraction role, then drafting role | Draft role receives verified claim cards after tool execution | 2 × 2,048 |

The specialized workflow uses two bounded roles on the same model, rather than independent autonomous agents. Equal output caps do not equalize prompts, available intermediate context, input tokens, or actual consumption. Both use the same source units, policy, validators, and financial engine.

Read `GET /v1/cases/{id}/evaluations/{evaluation_id}` for the draft, calculations, policy check, and model-call metadata. Raw provider responses remain in the local database and are not returned by this endpoint or committed to Git.

## OpenAI configuration and cost controls

Live consumption is disabled by default. Configure private `.env` values:

```dotenv
CDS_OPENAI_API_KEY=<private-api-key>
CDS_LLM_LIVE_ENABLED=true
CDS_LLM_MODEL=gpt-5.6-terra
CDS_LLM_BUDGET_USD=2.00
CDS_LLM_MAX_CALLS=64
```

Restart the API and worker after configuration changes. With Compose, recreate these services using `docker compose up --build --wait api worker`. Setting a key alone does not enable paid requests. Set `CDS_LLM_LIVE_ENABLED=false` and restart the services to disable new paid calls.

The adapter uses the [Responses API and strict structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs), with `store=false`, no hosted tools, no automatic retries, no redirects, and a fixed OpenAI endpoint. Model and standard token prices were checked on 2026-11-10: [GPT-5.6 Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra), US$2 per million input tokens and US$12 per million output tokens. Cached-input discounts are not assumed. Recheck pricing before extending the campaign.

The `phase4-openai` budget ledger is cumulative within one PostgreSQL database. Before HTTP dispatch, a transaction locks its budget row and durably reserves a conservative input/output upper bound. The application and database ceiling is US$2, including pending and uncertain calls; the application setting can lower that ceiling. There is also a 64-call default limit and a 60,000-byte request limit. Known usage is charged at the configured standard prices. Missing usage, transport failures, and unresolved reservations retain their full reservation. Completed identical requests replay stored output; failed or uncertain calls never automatically trigger another paid request.

This is a local application allowance, not an account-wide OpenAI billing limit. Separate databases and unrelated applications have separate usage. Preserve the ledger when restarting; do not recreate the database to resume the same campaign. Reservations protect against concurrent workers under the documented token-price assumptions. Billing reconciliation remains an operational responsibility.

## Persistence and failure behavior

External calls run outside business transactions. A separate heartbeat maintains the worker lease. Case/job locks and lease tokens fence persistence; expired workers cannot publish a draft. Calls have durable request hashes, prompt versions, usage, and cost records. Completed call output is reused during recovery.

Deterministic tools commit before external drafting, so a failed draft may retain valid facts and a policy check. The evaluation is then `FAILED_TERMINAL`, with no final draft. A refusal, incomplete output, malformed response, budget exhaustion, or grounding failure also terminates the job. Failed or unknown calls require explicit operational investigation rather than an automatic paid retry. Uploading a document clears the case's current-evaluation pointer; a historical job never resets that pointer when it finishes.

## Reproducible evaluation

After the ingestion demo is available:

```sh
uv run python scripts/evaluate_ai.py --provider mock --output storage/ai-mock.json
uv run python scripts/evaluate_ai.py --provider openai --repetitions 2 --output storage/ai-openai.json
```

Mock mode covers ten controlled variants with both workflows and incurs no model charges. OpenAI mode uses complete, conflicting, and instruction-injection CSV cases; two repetitions yield twelve workflow runs and up to eighteen calls. The campaign stops on a live failure. Reports are saved after each workflow and contain independent financial-reference agreement, complete grounded-draft checks, latency, token usage, prompt/model versions, and charged or reserved cost. Raw model logs and credentials are excluded.

The reports distinguish mock orchestration checks from live model measurements. Small controlled samples do not establish real-world accuracy, statistical superiority, lower manual effort, or a production service level. The user interface and human-review/report-export workflow remain Phase 5.
